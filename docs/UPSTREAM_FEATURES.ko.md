# TradingAgents 원본 기능과 한국판 사용 안내

이 문서는 설치된 한국판의 기반인 **v0.5.1 코드**를 기준으로 주요 사용자 기능과
확장 기능을 설명합니다. 2026-09-25 사용자 요청으로 v0.5.1 정식 태그를 병합했습니다.
향후 버전이 자동으로 반영되는 것은 아닙니다.

- [원본 저장소](https://github.com/TauricResearch/TradingAgents)
- [기준 v0.5.1 소스](https://github.com/TauricResearch/TradingAgents/tree/35543d0248bf89fcb92b17a15858ad0c0e940687)
- [한국판 실제 실행 예시](../README.ko.md)

## 1. 분석이 진행되는 순서

```text
종목 + 날짜 + 선택적 보유 내역
 → 시장·재무·뉴스·심리 분석
 → 상승론자와 하락론자의 토론
 → 연구 관리자의 결론
 → 트레이더의 제안
 → 공격적·보수적·중립적 위험 검토
 → 포트폴리오 관리자의 최종 판단
 → 보고서·판단 기록 저장
```

각 역할은 LLM 호출과 데이터 도구를 조합한 에이전트입니다. 여러 증권사의 독립적인
전문가가 제공하는 의견이 아니라, 설정된 모델이 역할별로 분석하는 구조입니다.

| 역할 | 하는 일 | 크래프톤을 분석한다면 |
|---|---|---|
| 시장·기술 분석가 | 가격·거래량·이동평균·RSI·MACD 등 검토 | 주가 추세와 변동성 확인 |
| 재무 분석가 | 재무제표·수익성·재무상태 검토 | 매출·이익·현금흐름을 검토 |
| 뉴스 분석가 | 기업 뉴스·공시·경제 환경 분석 | 신작·실적 관련 기사와 공시 확인 |
| 심리 분석가 | 확보한 뉴스·소셜 자료의 분위기 분석 | 긍정·부정 논거와 출처의 한계 구분 |
| 상승·하락 연구원 | 분석 보고서를 근거로 서로 반론 | 성장 기대와 실적·밸류에이션 위험 비교 |
| 연구 관리자 | 토론을 종합해 투자 의견 작성 | 어느 논거가 더 타당한지 정리 |
| 트레이더 | 가격 근거와 보유 내역을 고려한 제안 | 신규 접근 또는 기존 보유 대응 제안 |
| 위험 검토팀 | 서로 다른 위험 선호 관점에서 제안 평가 | 손실 가능성과 비중 위험 점검 |
| 포트폴리오 관리자 | 최종 판단과 근거 작성 | 최종 등급과 실행 조건 정리 |

위 사례는 역할 설명이며 실제 크래프톤에 대한 결론이 아닙니다. 모든 데이터 소스를
매번 반드시 호출하는 것은 아니며 제공자·모델·설정에 따라 실제 사용 자료가 달라집니다.

## 2. 판단 등급과 구조화된 결과

| 등급 | 의미 |
|---|---|
| Buy | 매수 의견 |
| Overweight | 비중 확대 의견 |
| Hold | 보유·중립 의견 |
| Underweight | 비중 축소 의견 |
| Sell | 매도 의견 |
| REVIEW | 정상 등급으로 해석하지 못해 재검토가 필요한 결과 |

연구 관리자·트레이더·포트폴리오 관리자는 구조화된 출력으로 결과를 전달합니다.
`REVIEW`를 보유 또는 매수로 바꿔 해석하면 안 됩니다. 등급은 자동 주문 지시가 아니며,
보고서에서 제시하는 조건·근거·자료 누락을 함께 읽어야 합니다.

## 3. 데이터와 시장 지원

| 원본 기능 | 사용 방식 | 한국판에서의 대응 |
|---|---|---|
| 가격·거래량 및 기술지표 | Yahoo Finance, Alpha Vantage 등 선택 | KIS 국내 원주가와 기술지표 |
| 재무·기업 정보 | Yahoo, Alpha Vantage, SEC EDGAR 도구 등 | KIS 기업 정보, DART 재무제표 |
| 기업·거시 뉴스 | 설정한 뉴스 제공자 | Naver Cloud 뉴스와 DART 공시 |
| 소셜 심리 | StockTwits·Reddit 등 지원 경로의 자료 | 원본 경로 유지. 한국 종목의 충분한 소셜 자료를 보장하지 않음 |
| 경제 통계 | FRED 및 과거 시점 제어 | ECOS 금리·환율·CPI·KOSPI·M2 |
| 예측시장 | Polymarket 도구 | 원본 도구 유지. 국내 종목별 이벤트 확보를 보장하지 않음 |
| 여러 시장·자산 | Yahoo가 지원하는 종목과 주가지수·ETF·암호화폐 심볼 | 한국 CLI는 국내 종목용. 해외 자산은 원본 설정 사용 |
| 데이터 공급자 선택 | `data_vendors`, 도구별 `tool_vendors` | 한국 프로필이 국내 공급자를 지정 |

도구별 설정은 카테고리 설정보다 우선합니다. 복수 공급자를 명시하면 순서대로 대체
조회할 수 있지만, 모든 공급자가 같은 자료를 제공하는 것은 아닙니다.
인증 실패·자료 없음·오래된 가격을 정상 데이터처럼 받아들이지 않도록 검증합니다.

## 4. 과거 시점 분석과 미래정보 방지

분석일을 정하면 가격·기술지표·뉴스·공시·거시자료 및 과거 판단 기록에 날짜 기준을
적용합니다. SEC EDGAR의 공시 접수일, FRED의 빈티지 등 제공자가 지원하는 시점 정보를
사용하는 경로도 있습니다. 트레이더가 참고하는 가격은 검증된 시세 자료에 연결합니다.

사용 예: “2026년 9월 18일 당시 자료로 삼성전자를 분석해줘.”
한국판 명령은 `analyze 005930 --date 2026-09-18`입니다.

완전한 과거 재현은 아닙니다. 현재 반환되는 뉴스 검색 결과, 정정 공시, 수정 통계 및
LLM 학습 지식의 한계가 있습니다. 한국판의 KIS 과거 기업현황과 ECOS 과거 빈티지처럼
정합성을 확보하지 못하는 자료는 사용 불가로 반환합니다.

## 5. 포트폴리오 컨텍스트

보유 종목·수량·평균매입가·현금·통화를 JSON으로 전달하면 트레이더와 위험 검토,
최종 판단에서 참고합니다. 한국판은 `analyze ... --portfolio portfolio.json`을 사용합니다.
파일 예시는 README에 있습니다.

보유 내역을 전달하지 않은 경우와 빈 `positions` 배열로 무보유임을 명시한 경우는
다릅니다. 자동 계좌 조회·주문·리밸런싱 실행 기능이 아닙니다.

## 6. 판단 기록과 사후 반성

완료된 판단은 지속적으로 저장됩니다. 같은 종목을 다음에 분석할 때 이전 판단의
관측 가능한 사후 수익률과 지역 벤치마크 대비 초과수익률을 평가하고, 반성 내용을
새 판단에 참고합니다. 모델 자체를 재학습하는 기능은 아닙니다.

기본 판단 로그는 `~/.tradingagents/memory/trading_memory.md`입니다.
`TRADINGAGENTS_MEMORY_LOG_PATH`로 위치를 바꿀 수 있습니다.
기본 사후 평가 기간은 5거래일이며 `holding_period_days` 설정으로 제어합니다.
과거 분석에는 해당 분석일에 알려질 수 있는 기록만 사용하도록 제한합니다.

## 7. 백테스트와 점수

종목 × 날짜 조합별로 동일한 분석을 실행하고 판단 결과를 평가합니다.
한국판 예: `backtest 005930,000660 --start 2026-09-01 --end 2026-09-08 --every 7`.

- 원본은 시장별 벤치마크를 사용하며 한국판은 코스피·코스닥 지수를 지정합니다.
- 결과는 확정·미확정·미평가 표본, 등급별 방향 적중률과 평균 초과수익률로 봅니다.
- 같은 run-id로 재실행하면 완료한 종목·날짜 조합은 건너뜁니다.
- 실시간 분석 로그와 백테스트 로그를 분리합니다.
- 보유 내역을 전달하면 모든 날짜에 동일한 내역을 적용합니다. 날짜별 매매 장부가 아닙니다.

주문 체결·수수료·슬리피지·복리 계좌 수익률을 계산하는 거래 시뮬레이터는 아닙니다.
원본 README의 모의거래소 실행 설명을 실제 브로커 연결 기능으로 해석하지 마세요.
설치된 코드에서 사용하는 결과물은 판단과 보고서, 평가 기록입니다.

## 8. 중단 후 재개와 보고서

LangGraph 체크포인트를 켜면 노드별 상태를 저장해 실패 후 재개할 수 있습니다.
기본은 꺼져 있습니다. 원본 CLI에는 `--checkpoint`가 있고,
한국판은 `.env`의 `TRADINGAGENTS_CHECKPOINT_ENABLED=true`로 설정할 수 있습니다.
한국 CLI에 원본의 `--checkpoint` 옵션을 그대로 붙이지 마세요.

체크포인트는 백테스트 run-id와 다릅니다. 전자는 한 분석 내부 단계의 복구,
후자는 여러 분석 중 완료한 조합의 중복 실행 방지에 사용합니다.
동일 종목·날짜·그래프 구조에서 재개하며 정상 완료 후 체크포인트는 정리됩니다.

종합 보고서와 단계별 Markdown 보고서, 실행 상태 로그를 저장합니다.
한국 CLI의 `--output`으로 보고서 폴더를 지정할 수 있습니다.
자세한 파일 구성과 읽는 순서는 README를 참고하세요.

## 9. 모델·분석 깊이·언어 설정

원본은 OpenAI, Anthropic, Google, xAI, DeepSeek, Qwen, GLM, MiniMax,
OpenRouter, Mistral, Kimi, Groq, NVIDIA, Azure OpenAI, AWS Bedrock,
Ollama 및 OpenAI 호환 엔드포인트를 지원합니다. 공급자별 인증과 모델 접근 권한이 필요합니다.
한국판은 여기에 Codex CLI 공급자를 추가했습니다.

| 설정 | 용도 |
|---|---|
| `quick_think_llm` | 일반 분석 등 빠른 처리 역할의 모델 |
| `deep_think_llm` | 깊은 판단 역할의 모델 |
| `max_debate_rounds` | 상승·하락 토론 횟수 |
| `max_risk_discuss_rounds` | 위험 검토 토론 횟수 |
| `output_language` | 보고서 출력 언어 |
| 공급자별 reasoning/thinking 설정 | 지원 모델의 추론 수준 |
| `llm_max_retries`, `max_tokens` | 공급자가 지원하는 재시도·출력 제한 |
| `news_article_limit` 등 | 입력 뉴스 수와 조회 범위 |

공급자마다 지원하는 옵션이 다릅니다. Codex CLI는 모든 API SDK 옵션을 동일하게
지원하지 않으며, 별도의 `CODEX_TIMEOUT`과 `CODEX_COMMAND`를 사용합니다.
토론 횟수를 늘리면 호출량과 시간이 늘고 결과가 반드시 좋아지는 것은 아닙니다.

## 10. 실행 방식과 개발 확장

| 방식 | 용도 |
|---|---|
| 원본 대화형 CLI `python -m cli.main` | 종목·날짜·모델·분석 깊이를 단계적으로 선택 |
| 한국 CLI `python -m cli.korea` | 국내 데이터와 Codex를 사용한 명령형 실행 |
| Python API `TradingAgentsGraph.propagate()` | 다른 프로그램에서 분석 실행·결과 활용 |
| Docker / Docker Compose | 원본의 컨테이너 실행, 선택적 Ollama 구성 |
| LangGraph 및 공급자 인터페이스 | 분석가 선택, 도구·공급자·그래프 확장 |

한국판에서 원본 대화형 CLI가 한국 CLI의 Codex 설정을 전부 대신하는 것은 아닙니다.
현재 설정으로 한국 종목을 실행할 때는 `cli.korea`를 사용하세요.
현재 PC의 Codex 로그인과 실행 파일은 Docker에 자동 전달되지 않습니다.

## 11. v0.5.1에서 반영한 변화

확인한 원본 README는 v0.5.1에서 패키지 경로 재정리, 선택적인 Jev 소셜 게시물 검사,
기본 모델 변경, 실행 격리와 SEC EDGAR 수정 사항을 소개합니다.
이 변경을 한국판에 병합하고 한국 데이터·Codex 연결을 새 경로에 맞춰 유지했습니다.
Jev 검사는 선택 기능이며 별도 설정 없이 활성화되지 않습니다. 한국 CLI와 현재 PC의
모델 설정은 Codex / gpt-6-astra / low를 유지합니다. 원본 기본 모델과 구분하세요.
새 버전 반영은 별도의 upstream 병합과 한국시장 회귀 검증이 필요한 작업입니다.
